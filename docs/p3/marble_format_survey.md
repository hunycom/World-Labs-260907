## 2. 오브젝트·레이어·시맨틱 분할 정보 유무

- **판정**: **없음 (None)**
- **세부 사실**:
  - Marble의 `.spz` 및 `.ply` 내보내기 데이터는 씬 전체가 하나의 통합된 가우시안 점군(Unified Splat Cloud)으로 출력됩니다.
  - 개별 가우시안 포인트에 대한 객체 인스턴스 ID, 레이어 분할 정보, 시맨틱 마스크는 내보내기 파일 내에 포함되어 있지 않습니다.
  - 생성 이전 단계에서 "Chisel" 에디터를 통한 대략적 공간 배치(Coarse Layout Blocking)는 가능하나, 최종 생성 및 내보내기된 점군은 단일 메쉬/점군으로 합쳐집니다.
  - 따라서 부품 단위 상호작용 및 물리 시뮬레이션을 수행하기 위해서는 외부 3D 세그멘테이션 모델(예: SAM 3D, 세그멘테이션 파이프라인) 또는 3D 바운딩 박스 기반 분할 도구를 런타임 이전 후처리 단계에서 적용해야 합니다.

## 3. 절대 척도(미터 단위) 보존 여부

- **판정**: **기본 자산 미보존 / API 메타데이터를 통한 변환 지원**
- **세부 사실**:
  - 내보내기된 3DGS 자산(`.spz`, `.ply`)의 좌표는 실제 미터 단위가 아닌 임의 모델 단위(Arbitrary Model Units)로 생성됩니다.
  - 단, API 응답에 포함되는 `semantics_metadata` 객체에 절대 척도 변환 파라미터가 제공됩니다:
    1. `metric_scale_factor`: 모델 좌표 및 스케일에 곱하여 미터 단위로 변환 ($X_{\text{metric}} = X_{\text{model}} \times \text{metric\_scale\_factor}$).
    2. `ground_plane_offset`: 스케일 적용 후 Y 좌표에서 감산하여 바닥면을 $y=0$으로 정렬 ($Y_{\text{metric}} = Y_{\text{model}} \times \text{metric\_scale\_factor} - \text{ground\_plane\_offset}$).
  - 좌표계: 기본 좌표계는 **OpenCV 좌표계** (+X 우측, +Y 하향, +Z 전방)를 사용합니다. Three.js/OpenGL 표준(+X 우측, +Y 상향, -Z 전방) 연동 시 Y, Z 축에 대한 $-1$ 스케일 변환이 필요합니다.

> **출처 및 인용 원문**:
> - URL: `https://docs.worldlabs.ai`
> - 인용: *"To convert these assets to a real-world metric scale, you must use the semantics_metadata object provided in the world response: metric_scale_factor (multiply every XYZ coordinate and isotropic scale by this factor to convert the model units into meters), ground_plane_offset (subtract this value from the Y coordinate to correctly align the ground plane at y=0)."*

## 6. 결론 및 P3-02 시사점

1. **상용 데모 자격 요건**: 고객 데모 및 백서에 3DGS 자산을 수록하려면 반드시 **Pro 등급($35/월)** 이상의 유료 플랜 또는 API 유료 크레딧으로 생성된 자산이어야 함 (Free 플랜 생성물은 상용 불가).
2. **분할 파이프라인 필수성**: Marble은 단일 점군(`.spz`/`.ply`)만 제공하고 오브젝트/시맨틱 분할 메타데이터를 제공하지 않으므로, P3-02 Task 2는 외부 분할 도구(SAM 3D 또는 BBox 클러스터링)를 거쳐 파트 매니페스트를 생성하는 파이프라인으로 구축되어야 함.
3. **척도 및 좌표계 보정 필수성**: `semantics_metadata`의 `metric_scale_factor` 및 `ground_plane_offset`을 적용하고, OpenCV $\to$ Three.js 좌표계 변환($\text{diag}(1, -1, -1)$)을 적용해야 물리 엔진(Rapier3D)의 미터 단위 및 접지면과 정합됨.
